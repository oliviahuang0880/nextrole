# 提問與選項撰寫判準

適用於 SKILL.md Phase 4（進階偏好）與任何需要使用者拍板的追問。目的是：**不要由 AI 腦補使用者的偏好**，而是把決策拆成使用者讀得懂、比得出差異的選項。

# Rule 1 - 每題必須先給足夠的 `Context`

- Level: `MUST`
- 提問前先說明：這題會影響什麼、答不同會有什麼不同結果、使用者需要知道的最小背景。
- 出現專有名詞（remote、field_terms、負向詞、threshold⋯）時先用白話解釋再問。
- 不可寫成空泛開場白，也不可把未確認的假設當既定事實塞進 Context。

## Good Example

```text
這題決定「評分」而不是「搜尋」。
填了領域之後，已經撈回來的職缺只要命中該領域的詞就會加分、排前面；
不填則用研究／分析／規劃／協作這類通用能力打分，不預設你該走哪個方向。
```

## Bad Example

```text
你想找什麼領域的工作？
```

# Rule 2 - `總結之提問` 必須是一句可直接作答的問題

- Level: `MUST`
- 延續 Context，濃縮成一句自然、清楚、能直接引出選項的問題。
- 不可在一句裡混入多個決策軸；需要多個面向就拆成多題。

# Rule 3 - 選項用 Markdown 表格或編號清單，固定附 `Others`

- Level: `MUST`
- 每題列出可比較的選項，標明單選或複選。
- 最後一定要有 `Others / 其他`，讓使用者自由補充。
- 請使用者用編號回答；未收到回答前**停止**，不得自行假設答案或先寫入 profile。
- 不使用 Ask Tool，直接在對話中輸出，讓使用者看得到完整的 Context 與選項。

# Rule 4 - 推薦選項：只在技術性選項給，領域偏好題禁止給

- Level: `MUST`
- 純技術性、有客觀優劣的選項（例如「亞太會掃 7 個城市、整跑 5–8 分鐘」）**可以**標一個推薦選項並說明理由。
- 涉及使用者職涯方向的題目（領域偏好、負向詞）**不得**標推薦選項，也不得暗示哪個比較好。
- 理由見 `rules/中立與加權判準.md`：方向由使用者決定，AI 只負責呈現差異。

## Bad Example

```text
2️⃣ UX（推薦：你之前是設計背景，這個最適合你）
```

# Rule 5 - 每輪 1–3 題，整場累計不超過 5 題

- Level: `SHOULD`
- 一次丟太多題會讓使用者放棄。優先問影響範圍最大的。
- 地區（4a）與負向詞（4d）是必問；領域（4b）與 JD（4c）是選填，使用者說「跳過」就跳過。
