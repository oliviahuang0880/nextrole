# 中立與加權判準

這份規則定義 NextRole 最核心的立場：**不替使用者預設職涯方向**，以及三種「加權／篩選」機制各自負責什麼。

# Rule 1 - 使用者沒指定領域時，一律用中立技能關鍵字

- Level: `MUST`
- 不得用「他之前是 X 行業／他是 X 職位」去推測哪些職缺比較適合他，也不得替他斷定某個領域不適合。
- 分數只呈現「這份職缺跟你的能力有多像」，適不適合由使用者自己判斷。
- 這條約束同時適用於：搜尋關鍵字的挑選、評分、以及最後回報時的措辭。

## Bad Example

```text
我幫你把硬體和 ML 的職缺濾掉了，那些跟你的設計背景不合。
```

## Good Example

```text
分數前 20 名裡有 3 筆是硬體相關的，命中的是「研究」「跨部門協作」。
要不要看你自己決定。
```

# Rule 2 - 三種機制分工，不可混用

- Level: `MUST`

| 機制 | 寫在哪 | 影響什麼 | 何時設定 |
|---|---|---|---|
| `candidate_titles` | profile | **搜尋**：用職稱撈職缺，排搜尋詞第一順位 | Phase 4a 想找的職稱 |
| `method2_positive` 的 `q:true` | profile | **搜尋**：用通用能力詞撈職缺 | 技能問卷產出（35 題裡只有 13 題會變搜尋詞） |
| `field_terms` + `use_field_terms` | profile | **評分**：命中該詞加分，排前面 | Phase 4b 領域偏好 |
| `extra_queries` | 只用於這次執行，不寫 profile | **搜尋**：拓寬撈得到的範圍 | Phase 4c 貼 JD |
| `negative` | profile | **排除／扣分** | Phase 4d 負向詞 |

- `field_terms` 動的是「已經撈回來的職缺怎麼排序」，`extra_queries` 動的是「撈不撈得到」。兩者不衝突也不重疊，不可拿其中一個代替另一個。
- ⚠️ **想讓某類職缺「撈得到」，只能靠 `candidate_titles` 或 `extra_queries`。**
  `field_terms` 加再多都沒用 —— 它只能把已經在手上的職缺往前排。
  這是最容易搞錯的一條：使用者說「我想多看到 X」時，要先判斷他是要「撈到」還是要「排前面」。

# Rule 3 - `use_field_terms` 預設 false

- Level: `MUST`
- 使用者沒有主動填領域偏好 → `scoring.use_field_terms` 保持 `false`，純通用能力評分。
- 使用者填了 → 生 8–15 個該領域常見的技能／工具／職能詞（繁體中文，不要公司名／地名），**列給使用者確認後**才寫進 `field_terms`（每個 `weight: 3`）並把 `use_field_terms` 設 `true`。
- 寫入後要提醒：「加了之後評分會偏向這方向，命中這些詞分數會變高」。
- 使用者之後說「回到中立」→ 設回 `false`。

# Rule 4 - 沒有預設負向詞

- Level: `MUST`
- 這個 skill **不替使用者預設**「實習／兼職／電話銷售」等該不該排除。全部由 Phase 4d 問出來。
- 使用者回「沒有」、空字串、或全不勾 → `negative` 陣列**不動**，零負向詞。

## 寫入格式

- 一般排除項 → `{"term": "<中文>", "en": "<英文>", "exclude_if_title": true}`
  - 出現在**職稱** → 整筆剔除；只出現在 JD 內文 → 扣分（仍看得到，排後面）。
- 全面排除項（例如電話銷售） → `{"term": "電話銷售", "en": "telesales", "exclude": true}`
  - 任何地方命中即剔除。

## 常見選項英文對照

| 選項 | term | en |
|---|---|---|
| A | 實習 | intern |
| B | 兼職 | part-time |
| C | 工讀 | (無) |
| D | 約聘 | contractor |
| E | 自由接案 | freelance |
| F | 顧問 | consultant |
| G | 電話銷售 | telesales |

- 使用者自由打的中文詞 → 順手補英文翻譯寫進 `en`；使用者直接打英文 → `term` 放英文、`en` 留空。

# Rule 5 - JD 抽詞只抽中立技能／領域詞

- Level: `MUST`
- 從使用者貼的 JD 抽 5–8 個繁體中文關鍵字，**不要公司名、地名、人名**。
- 抽完先列給使用者確認：「我抽到這些⋯要全部加入嗎？還是挑幾個？」確認後才併進 `extra_queries`。
