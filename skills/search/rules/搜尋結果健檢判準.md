# 搜尋結果健檢判準

`run_search.py` 跑完會在 stdout 印一段 `━━━ 健檢 ━━━` 區塊，並在最後一行印 `健檢代碼：<CODE>,<CODE>,…`。**不得**跳過這段直接跟使用者說「完成了」。

# Rule 1 - 一定要讀健檢代碼再回報

- Level: `MUST`
- 看到 `健檢代碼：OK` 才可以用「完成」的語氣回報。
- 出現任何其他代碼，必須依下表向使用者說明**發生什麼事、可能原因、建議怎麼做**，不得靜默通過。
- 腳本本身不會因為健檢失敗而 exit 非 0（避免打斷排程），所以「指令跑完沒報錯」不等於結果健康。

# Rule 2 - 代碼對照與處置

| 代碼 | 意思 | 要跟使用者說什麼 |
|---|---|---|
| `OK` | 一切正常 | 依 `templates/search-summary.md` 正常回報 |
| `NO_QUERIES` | profile 裡沒有任何 `q:true` 的搜尋詞 | 問卷沒跑完或關鍵字被清空。建議重跑技能問卷，或手動把幾個技能標成搜尋詞 |
| `NO_RAW` | 三站合計撈到 0 筆 | 多半是網路不通或三站同時擋爬蟲。建議稍後再試；連續失敗就是爬蟲需要修 |
| `SOURCE_DEAD:<站名>` | 某一站撈到 0 筆、其他站正常 | 該站可能改版或擋了。明講「這次結果不含 <站名>」，別讓使用者以為已經搜過全部三站 |
| `ALL_FILTERED` | 有撈到職缺，但被地區／排除條件濾到 0 筆 | 條件太緊。列出目前的 `regions`、`allowed_cities`、`negative`，問要不要放寬（例如多加「全遠端」或拿掉某個城市限制） |
| `NO_RECOMMENDED` | 有結果但推薦區 0 筆 | 分數都沒過門檻。報出最高分是幾分、門檻是幾分，建議把 `scoring.threshold` 調低，或補領域關鍵字 |
| `THIN_RESULT` | 總筆數 < 10 | 太少了。建議放寬地區、加 `--queries`、或貼一份喜歡的 JD 抽更多搜尋詞 |
| `NO_OUTPUT` | HTML／CSV 沒寫出來或是空檔 | 這是真的壞了。把 stdout 給使用者看，不要宣稱有報表 |

# Rule 3 - 處置建議要具體到可以直接執行

- Level: `MUST`
- 不可只說「建議放寬條件」，要給實際指令或實際要改的值。

## Good Example

```text
撈到 240 筆，但地區條件濾到剩 0 筆 — 你目前只收「台北、新竹」。
要不要加上「全遠端」？我可以幫你改 profile 再用快取重算，不用重爬：
  uv run run_search.py --from-cache
```

## Bad Example

```text
結果是 0 筆，可能是條件太嚴格，可以考慮調整看看。
```

# Rule 4 - 健檢不改變中立原則

- Level: `MUST`
- 建議放寬條件時，不得順手替使用者加上某個領域偏好或推測她「應該」找哪種工作。
- 只能建議調整**機制層面**的參數：地區、門檻、搜尋詞數量、負向詞。方向仍由使用者決定（見 `rules/中立與加權判準.md`）。
