# 技能問卷對話節奏判準

適用於 SKILL.md Phase 3（35 題技能問卷）。資料來源是 `references/method2_skills.json`，它有 6 組（rounds），每組有 `scenario` 情境句 + 一組技能。

# Rule 1 - 進新組時先唸組情境，每題再重貼一次

- Level: `MUST`
- 進入新組時，先把該組 `scenario` 完整唸給使用者一次。
- 之後每一題都要把組情境用 quote（`>`）重貼在問題上方，讓使用者隨時看得到當下情境。

# Rule 2 - 每題都要寫一個更具體的小情境

- Level: `MUST`
- 不可只把組情境貼過來當題目情境。每題要另外寫一個具體的工作場景。
- 即使第二題之後也一樣，不得因為「前面講過了」而省略。

## Good Example

```text
情境：老闆丟你一個全新的題目「我們要不要做這個產品？」，沒有人做過，也沒有資料。
你要去訪談使用者、查競品、看市場報告，把事情查到水落石出。
```

## Bad Example

```text
Q2.「分析」— 1 On Fire / 2 Heating Up / 3 Burnout / 4 Cold
```

# Rule 3 - 四個選項要用該題情境的語言客製化

- Level: `MUST`
- 不可只列 `On Fire / Heating Up / Burnout / Cold` 的名稱，要用這一題的情境去描述每個選項實際是什麼感覺。

```text
1️⃣ **On Fire** — 一頭栽進去查到忘記吃飯，這種題目最有趣
2️⃣ **Heating Up** — 做得還不夠扎實，但很想練到能獨立扛這種題目
3️⃣ **Burnout** — 查得來，但常做會累，比較想偶爾為之
4️⃣ **Cold** — 看到一堆未知資訊就頭大，能不查就不查
```

# Rule 4 - 每題都要顯示進度條

- Level: `MUST`
- 10 字寬 ASCII，`▓` 填、`░` 空，放在「Q N.」上方一行。
- 公式：`filled = max(1, round(10 * Q / 35))`，剩下用 `░` 補滿。

```text
▓░░░░░░░░░  1/35
▓▓░░░░░░░░  5/35
▓▓▓░░░░░░░ 10/35
▓▓▓▓▓░░░░░ 17/35
▓▓▓▓▓▓▓▓░░ 28/35
▓▓▓▓▓▓▓▓▓▓ 35/35
```

- 用意：讓使用者隨時知道還剩幾題，減少「這還要做多久」的疲勞感。省略進度條會直接拉高中途放棄率。

# Rule 5 - 回答處理

- Level: `MUST`
- 使用者回 `1`/`2`/`3`/`4` → 立刻問下一題，不要多餘寒暄。
- 使用者改用文字描述實際工作情境 → 由你判斷分類，回覆「判定為 X — 理由」再接下一題。
- 每題末尾附一行：`💬 也可以描述實際工作情境，我幫你判斷。`

# Rule 6 - 每組結束問一次補充

- Level: `MUST`
- 「這組（XX類）有沒有想補充的？例如某個技能跟特定領域連在一起？沒有就回『沒有』」
- 存進 `notes`，key 是該組的 category。

# Rule 7 - 整組可以跳過

- Level: `MUST`
- 每組開頭唸完組情境之後，加一句：**「這組跟你想找的工作沒關係就說『跳過』。」**
- 使用者說跳過 → 該組所有技能都不寫進 `classifications`，直接進下一組。
  `build_profile.py` 對沒出現的 key 不會給任何權重，等同於「未表態」，**不是** cold。
- ⚠️ 跳過會少掉搜尋詞。35 題裡只有 13 題會變成搜尋關鍵字，分佈在各組：

  | 組 | 會變成搜尋詞的 |
  |---|---|
  | 分析類 | 研究、分析、建立指標 |
  | 管理類（一） | 專案管理、規劃 |
  | 管理類（二） | 流程改善、解決問題 |
  | 人際類（一） | 教學、顧問 |
  | 人際類（二） | 談判、客戶服務 |
  | 創意類 | 設計、說故事 |

- **跳超過三組就要提醒**：「這樣搜尋詞會很少，可能撈不到什麼。Phase 4a 的職稱會補上，但你也可以回頭補做幾組。」
- 全部六組都跳過 → 不阻止，但明講「等於沒有技能關鍵字，只會用你等一下給的職稱去搜」。

# Rule 8 - 內部累積不給使用者看

- Level: `MUST`
- `classifications`: `{<skill_key>: "on_fire"|"heating"|"burnout"|"cold"}`（跳過的組不列入）
- `notes`: `{<round_category>: "補充文字"}`
- 問卷進行中不要把這兩包 dump 給使用者看，跑完 `build_profile.py` 後才依 `templates/keywords-report.md` 呈現結果。
