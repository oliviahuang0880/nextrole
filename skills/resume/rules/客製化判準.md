# 客製化判準

## 鐵則：事實不動，只調措辭、補既有實績、調順序

客製化能做的三件事：

1. **調順序** — 把命中 JD 重心的經歷、專案、bullet 往前排。
2. **換措辭** — 同一件事換一組貼近 JD 用語的講法。
   例：主履歷寫「收斂需求」，JD 通篇在講「規格交付」，就改成「把需求收斂成工程可直接開發的規格」。
3. **補既有實績** — 把主履歷因為篇幅砍掉、但這次剛好命中的成果補回來。

⛔ 不能做的：

- 新增使用者沒做過的經歷或專案
- 生出主履歷裡沒有的數字
- 把職稱寫成比實際更高的層級
- 把「參與過」寫成「主導」
- 把假設或計畫寫成已完成的事

⚠️ 這幾條不是保守，是**風險控制**：履歷寫得到的，面試就會被追問。
追問答不出來的傷害，遠大於履歷多一行的好處。

## 動刀順序

1. **先定重心。** 從 JD 的必要職責找出主軸（通常兩到三條）。
2. **再排段落。** 命中主軸的經歷往前，不相關的往後並縮短 — 縮短，不是刪掉。
   完全刪掉會出現時間空白，反而要被解釋。
3. **然後改 bullet。** 每一條 bullet 檢查三件事：
   - 有沒有**動詞＋做了什麼＋結果**？只有動作沒有結果的 bullet 是廢的
   - 結果有沒有**數字或前後對比**？沒有的話，素材裡有沒有可以補上的
   - 用語有沒有貼近 JD？
4. **最後檢查長度。** 一頁到兩頁。第三頁通常沒人看。

## 每個 bullet 的檢查

| 寫法 | 問題 |
|---|---|
| ⛔「負責產品規劃」 | 只有職責範圍，沒有做了什麼、也沒有結果 |
| ⛔「優化了使用者體驗」 | 沒有具體行動，沒有可驗證的結果 |
| ⭕「重整需求收斂流程，規格返工率下降四成」 | 行動＋結果＋數字 |

沒有數字的成果也可以寫，但要有**可驗證的結果**（誰用了、改變了什麼），
不能只有「提升了」「改善了」。

## 開頭要留客製方向

檔案第一行寫：

```
> 客製方向：<這份 JD 的重心一句話>｜底本：<用了哪一版>｜<日期>
```

之後回頭看，才知道當初為什麼把某段拉到前面。同一家公司二面要補材料時也用得上。

## 缺口怎麼處理

**履歷不是處理缺口的地方。**

- JD 標「尤佳／加分」而使用者沒有的 → 不寫。主動說「我沒有 X」等於替對方放大一個他原本沒在意的問題。
- JD 標「必要」而使用者沒有的 → 也不在履歷上解釋。那是**契合度診斷的硬門檻**該處理的
  （投不投的判斷），以及**面試**該處理的。

履歷的篇幅全部留給「我會什麼、我做過什麼」。
