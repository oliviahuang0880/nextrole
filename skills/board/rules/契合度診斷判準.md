# 契合度診斷判準

評分（0–100）是**廣篩**用的：它只看關鍵字命中，不懂脈絡。
契合度診斷是**決定投不投**用的：讀完整 JD，判斷這一家值不值得花兩小時客製履歷。
兩者不可互相取代，也不要拿來比大小。

---

## 三個指標

### 指標一：產業關係（1–4）

問的是「使用者上一份工作的產業，跟這家公司的產業有多近」。

| 分 | 判準 |
|---|---|
| 1 | 完全無關 |
| 2 | 有點關係（有共通的使用者情境或技術，但不是同一門生意） |
| 3 | 上下游（是彼此的客戶或供應商） |
| 4 | 完全相關（同產業） |

⚠️ **這一指標通常不是決定因素**，不要因為它低就勸退。很多人的實際錄取紀錄裡，
產業關係全都只有 1–2 分。它只在對方明講「必須有 X 產業經驗」時才致命 — 而那是硬門檻，不是這一格。

### 指標二：職務重疊面積（1–4）

問的是「JD 列的職責，使用者實際做過多少」。**看的是做過，不是會做**。

| 分 | 判準 |
|---|---|
| 1 | 無 |
| 2 | 低（只重疊一兩項邊緣職責） |
| 3 | 中（主要職責重疊一半左右） |
| 4 | 高（主要職責幾乎都做過） |

⭐ 實務上這一格最能預測有沒有面試。逐條對照 JD 的職責清單，
每一條標「做過／類似／沒有」，再給分 — 不要憑印象給。

### 指標三：條件符合程度（1–5）

問的是「年資、職級、技能要求、語言」這些硬條件的吻合度。

| 分 | 判準 |
|---|---|
| 1 | 無 |
| 2 | 低 |
| 3 | 中 |
| 4 | 高 |
| 5 | 過高 |

⚠️ **5 分不是好事**。過高可能被視為大材小用、擔心留不住而不敢用。
給 5 分時要在建議裡提醒這個風險。

### 總分（滿分 13）

| 總分 | 意義 |
|---|---|
| < 6 | 勝率低，不建議投 |
| 7–9 | 靠聚焦放大可以拉高面試率 — 客製履歷的投資報酬率最高的區間 |
| 10–13 | 條件很好。**投了卻沒有面試就要深究**，通常是踩到硬門檻或履歷沒把重疊面積講清楚 |

判定用 `config.json` 的 `fit_threshold`（預設 7）：
`總分 ≥ 門檻+1` → 投；`= 門檻` → 邊緣；`< 門檻` → 不投。
**踩到硬門檻一律判「不投」，不管總分多少。**

---

## 硬門檻（框架沒有，但最關鍵）

三個指標是連續的程度分，但有些條件是**開關**：一條不符合就直接被刷掉，
再怎麼修辭都救不了。這類條件不進三指標，另外標。

判斷方式：這條要求是不是**用文字修飾解決不了**的？

- 「英文聽說讀寫流利」「需與海外團隊全英文協作」→ 是
- 「必備 N 年以上 X 職務年資」→ 是（差一年可能還好，差三年不行）
- 「必備某產業／某類產品的實戰經驗」→ 是
- 「需具備某張證照／某個學歷門檻」→ 是
- 「熟悉 X 工具尤佳」「加分項」→ **不是**。「尤佳」是加分，不是門檻

⚠️ 只有寫在**必要條件**區的才算。JD 常把想要的東西全部列出來，
要區分「必備」與「尤佳」— 這是評分時最常誤判的地方。

使用者自己的清單在 `config.json` 的 `hard_blockers`，評分時先比對這份。
發現新的就建議他加進去。

---

## 產出格式

每一筆評成一段，給使用者看，不要只給總分：

```
【公司名 · 職缺名】評分 NN
  產業關係　N／4　<一句理由>
  職務重疊　N／4　<逐條對照的結論，點出哪幾條做過、哪幾條沒有>
  條件符合　N／5　<年資／技能／語言的吻合度>
  硬門檻　　無／🚫 <踩到哪一條>
  ──────────
  總分 N／13 → 投／邊緣／不投
  <一句話建議：如果投，履歷該把哪一段放前面；如果不投，是差在哪>
```

最後一行最有用。**「不投」也要講清楚差在哪** — 使用者才知道是這次不合適，
還是有個缺口值得長期補。

---

## 這份判準不做的事

- **不替使用者決定要不要投。** 給分數與理由，投不投是他的事。
- **不猜 JD 沒寫的東西。** 找不到就寫「JD 未提」，不要用產業常識補。
- **不因為分數低就勸退。** 7–9 分正是客製化最划算的區間。
