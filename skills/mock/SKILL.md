# 模擬面試

大多數人的問題不是準備不夠，是**臨場只講出準備量的三成**。
所以這個流程的重點不是出題，是**一直逼證據**。

## Output Contract

- 復盤寫 `~/.nextrole/interviews/<job_id>/mock-YYYYMMDD.md`。
- 新發現的弱點 append 進 `~/.nextrole/kit/weaknesses.md`，**不要覆寫既有的**。
- **一次只問一題。** 一次丟五題他沒辦法練。
- 不要因為「方向對」就放過。每題答完都要問「所以你做過哪一次？」

# SOP

## Phase 0 -- 開場先確認四件事

1. WRITE 問：**哪家公司／第幾輪／難度／回饋方式**。
   - **難度**：溫和・正常・壓力面・**混合實戰**（不告訴他面試官是誰，混問各輪題目）
     ⭐ 混合實戰效果最好 —— 他無法預判該端哪套素材，最接近真實。
   - **回饋方式**：每題即時點評（學習效率高）／全程不打斷、最後總評（練節奏）
   - 不同輪次問的東西差很多，缺輪次就問。
2. READ 讀 `~/.nextrole/interviews/<job_id>/qa.md`、`~/.nextrole/kit/`
   （事實庫、故事庫、口徑、**弱點清單**）。
3. THINK ⚠️ **這家還沒有 `qa.md` 時**（他想臨時練一家還沒準備的公司）：
   先問有沒有 JD／官網，**至少跑一次 `/nextrole:interview`「準備一家公司」的第 2 和第 4 步**
   （研究產品在解什麼問題、找出這份 JD 的異常之處），否則只問得出通用題，模擬價值折半。
   時間不夠就明講：「這場只練通用題，客製題等資料做出來再練。」

## Phase 1 -- 出題

1. READ 讀 `rules/出題配比.md` 與 `rules/常見失分模式.md`。
2. WRITE 照配比出題，**一次一題，等他答完再問下一題**。
3. WRITE 每題答完給即時回饋（除非他選了最後總評）：講得好的地方、漏掉的地方。
4. THINK 盯 `rules/常見失分模式.md` 的通用清單 ＋ `~/.nextrole/kit/weaknesses.md`
   的個人累積。個人清單優先 —— 那是他真的犯過的。

## Phase 2 -- 總評

1. WRITE 給總評：**共通模式**（不是逐題重複）、哪幾題可以直接上場、哪幾題要回去補。
2. THINK ⚠️ 如果他自評「整場搞砸了」，**先把他的感受和實際紀錄並排給他看**，再談要修什麼。
   順著「我搞砸了」往下走，真正該修的一兩件事會被情緒淹掉。

## Phase 3 -- 寫回

1. WRITE 寫 `~/.nextrole/interviews/<job_id>/mock-YYYYMMDD.md`，
   照 `templates/mock-review.md` 的四段結構。
2. WRITE 這次冒出來的新弱點 append 進 `~/.nextrole/kit/weaknesses.md`。
   已經在清單上的就不要重複加，改成註記「又出現一次」加日期 —— 重複出現代表要優先修。
3. WRITE 模擬中冒出新的可重用故事就加進 `~/.nextrole/kit/stories.md`。
4. WRITE 有設定試算表的話，**問過使用者之後**才同步
   （見 `skills/interview/rules/試算表格式規範.md`）。

## 已知地雷

- `cd ~/.nextrole/bin` 失敗時（通常是 plugin 更新過，symlink 指向舊版本），跑一次 `/nextrole:setup` 就會重新指好。
- ⚠️ **客製題要故意換問法，不要照 `qa.md` 的標題問。**
  照標題問測不出真實狀態 —— 他對得上標題就答得好，換個問法才看得出有沒有真的懂。
- ⚠️ **追問才是真正的考點。** 準備過的題通常答得不錯，追一層就會露出「只講觀點不接證據」。
- ⚠️ 不要只問準備過的題。刻意問**沒有腳本**的題，要求他用「我真的做過，所以我講得出來」
  的方式回答，不准說「我沒準備」。
